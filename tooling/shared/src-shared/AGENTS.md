# tooling/shared/src-shared/ — CANONICAL Shared Boilerplate

## Purpose

Master copies of all synced TypeScript boilerplate files. Every file here is propagated to all downstream plugins' `src/shared/` directories via the sync engine. This is where deterministic plugin patterns are maintained ecosystem-wide.

## Key Files

| File | Purpose | Synced To |
|------|---------|-----------|
| `plugin-logger.ts` | Structured logging with debug mode, console/notice routing | All plugins' `src/shared/plugin-logger.ts` |
| `plugin-notices.ts` | Managed notice system with muting, templates, interpolation | All plugins' `src/shared/plugin-notices.ts` |
| `settings-migration.ts` | Deterministic schema migrations for plugin settings | All plugins' `src/shared/settings-migration.ts` |
| `debounce-controller.ts` | Debounce with rerun tracking and proper cleanup | All plugins' `src/shared/debounce-controller.ts` |

## Sync Mechanism

Each file carries a sync marker in its header:

```typescript
// Synced from obsidian-boiler-template/tooling/shared/src-shared/plugin-logger.ts. Do not edit this file directly.
```

Downstream plugins see this comment and know:
1. File is managed by the sync engine
2. Manual edits will be overwritten on next sync
3. To request changes, modify the canonical file and sync

## File Descriptions

### plugin-logger.ts
- Public API: `PluginLogger` class
- Features: debug mode toggle, log level routing, formatted console output, notice integration
- No state mutation — logs are side-effect-free reads
- Used in UI and domain code for structured logging

### plugin-notices.ts
- Public API: `PluginNotices` class
- Features: notice templating with interpolation, mute management, styled fragments
- Manages notice lifecycle and cleanup
- Depends on Obsidian's `Notice` API
- Prevents notice spam with smart muting

### settings-migration.ts
- Public API: `migrateSettings()` function
- Features: pipeline of migration functions, shallow copy semantics
- Deterministic — migrations are pure functions
- Used in `loadSettings()` to upgrade old settings schemas

### debounce-controller.ts
- Public API: `DebounceController` class
- Features: debounce with rerun tracking, async-safe cleanup
- Handles edge case: if `onRun()` is slow and `markDirty()` called again, rerun after current completes
- No state leaks — timer properly cleaned up on dispose

### styles.base.css
- Base styles for PluginNotices DOM structure
- Flat design, Obsidian-compatible colors
- Minimal — plugins extend with custom styling

## Change Protocol

**To improve a synced file:**

1. Edit the canonical file in `tooling/shared/src-shared/`
2. Test thoroughly: `pnpm test`, `pnpm build`
3. Document change in commit with git trailers (Constraint, Rejected, etc.)
4. Run `pnpm sync:plugins` to propagate
5. Verify all downstream targets updated: `git status` should show new files in each submodule
6. Create a PR with the updated canonical file + all downstream updates

**Breaking changes:**
- API signature changes require deprecation period or coordinated update
- Consider backwards compatibility before modifying public interfaces
- If breaking: document in commit and PR with rationale

**Testing synced files:**
- Unit tests in boiler-template's `test/shared/` cover all boilerplate
- Before syncing, verify: `pnpm test` passes
- After syncing, spot-check one downstream plugin: `pnpm test` in that plugin too
